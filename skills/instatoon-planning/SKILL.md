# 인스타툰 기획

## 입력과 참조

주제·키워드 또는 사용자가 제공한 경험, 시리즈의 독자·톤을 입력으로 사용한다. [기획 기준](../../references/planning.md)과 [데이터 계약](../../references/contracts.md)을 읽는다.

## 절차

1. 사용자 사실과 에이전트가 제안하는 허구를 구분한다. 주제가 구체적이면 후보 선택을 불필요하게 반복하지 않는다.
2. 소재가 넓으면 사건·공감 지점·결말이 서로 다른 후보를 2~3개 제시한다. 사용자가 선택을 위임했다면 기준과 선택 이유를 기록하고 진행한다.
3. 독자, 감정 목표, 중심 사건, 단편/연재, 결말 또는 다음 화 질문을 확정한다. 초기 분량은 4~6컷, 최대 10컷이다.
4. `episode.json`의 documents.brief에 기획과 제안값을 저장한다. 그림에 필요한 등장인물과 장소를 함께 적되 캐릭터 외형이나 화풍을 임의로 승인하지 않는다.

## 완료 조건

한 문장으로 사건과 감정 변화를 설명할 수 있고 단편의 결말 또는 연재의 다음 화 질문이 정해져 있다. 기획만 요청했다면 여기서 종료한다. 전체 제작에서는 결과를 전체 진행 스킬에 반환해 콘티로 연결한다.

## 저장 방식

[데이터 계약](../../references/contracts.md)의 v2를 따른다. 현재 정보는 series.json·episode.json, 에피소드 변경 이력은 history.jsonl로 관리한다. 컷별·단계별 JSON이나 매 수정 시 전체 snapshot을 추가하지 않는다.
