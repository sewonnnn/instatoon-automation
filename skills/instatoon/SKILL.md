# 인스타툰 전체 진행

## 입력과 준비

사용자 요청과 기존 프로젝트를 확인하고 [진행 규칙](../../references/workflow.md), [데이터 계약](../../references/contracts.md)을 읽는다. 실제 기능을 실행하기 전에 [tool 현황](../../references/tools.md)을 확인한다. 모든 산출물 경로는 저장소 루트 기준이다.

주제만으로 시작할 수 있다. 독자·톤·분량은 요청에서 추론해 제안값으로 기록한다. 주제 자체가 없고 기존 작업에서도 찾을 수 없으면 주제를 묻는다. 여러 프로젝트 중 대상을 특정할 수 없으면 덮어쓰기 전에 대상을 확인한다.

## 작업 선택

| 요청 또는 현재 단계 | 읽을 스킬 |
| --- | --- |
| 소재 후보와 이야기 방향 | [기획](../instatoon-planning/SKILL.md) |
| 새 스타일 또는 스타일 변경 | [스타일](../instatoon-style/SKILL.md) |
| 새 캐릭터 또는 외형 변경 | [캐릭터](../instatoon-character/SKILL.md) |
| 컷 구성·대사·결말 | [콘티](../instatoon-storyboard/SKILL.md) |
| 그림 생성·표정·구도 수정 | [그림](../instatoon-drawing/SKILL.md) |
| 말풍선·한글·최종 출력 | [식자](../instatoon-lettering/SKILL.md) |

전체 제작은 요청 정리 → 스타일 승인 → 캐릭터 승인 → 기획 확정 → 콘티 승인 → 그림 → 식자 → 최종 승인 → 출력 순서다. 주제·독자·톤은 스타일 탐색 전에 정리한다. 기존 승인 자원은 버전과 적용 대상을 확인해 재사용한다. 필요한 스킬만 순서대로 읽으며 별도 에이전트 실행을 요구하지 않는다.

## 진행 관리

1. 요청 범위와 산출물 상태를 확인하고 가장 먼저 필요한 작업을 선택한다.
2. 전문 스킬이 반환한 파일·입력 버전·QA 결과를 확인한다. 완료와 사용자 승인을 구분한다.
3. 승인 단계에서는 실제 샘플 또는 콘티를 보여주고 선택·수정을 받는다. 이미 해당 버전에 승인한 경우 다시 묻지 않는다.
4. 수정 요청에는 진행 규칙의 영향 범위를 적용한다. 관련 없는 그림을 재생성하지 않는다.
5. 다음 작업, 미완료 이유, 승인 대상과 재시도 횟수를 저장한다. 기능이 없으면 가능한 기획·명세까지 저장하고 필요한 기능을 정확히 알린다.

## 완료 조건

요청된 범위의 파일과 QA가 저장되어 있어야 한다. 전체 제작 완료는 승인된 두 크기의 PNG와 episode.json의 exports 기록이 존재할 때만 선언한다. 사용자에게 결과 경로와 남은 선택 사항을 전달한다. 게시나 댓글 분석은 별도 요청 범위다.

## 저장 방식

[데이터 계약](../../references/contracts.md)의 v2를 따른다. 현재 정보는 series.json·episode.json, 에피소드 변경 이력은 history.jsonl로 관리한다. 컷별·단계별 JSON이나 매 수정 시 전체 snapshot을 추가하지 않는다.
