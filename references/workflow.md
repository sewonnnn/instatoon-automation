# 진행과 승인 규칙

## 시작과 재개

전체 제작은 요청 정리 → 스타일 → 캐릭터 → 기획 → 콘티 → 그림 → 식자 → 출력으로 진행한다. 구체적인 소재 선정 전에도 요청의 주제·독자·톤을 스타일 입력으로 사용한다. 기획만, 스타일만 등의 요청은 해당 범위에서 끝낸다.

기존 프로젝트는 series.json과 episode.json을 읽고 현재 입력 버전, 파일 존재, 해시, QA, 승인 대상을 확인한다. 입력이 바뀐 산출물은 stale로 표시하고 완료로 취급하지 않는다. 승인된 기존 스타일과 캐릭터는 재승인 없이 재사용한다.

스타일·캐릭터 자원은 각각 상태를 갖는다. 에피소드 phase는 planning, storyboarding, drawing, lettering, final_review, exported다. status는 ready, running, awaiting_user, needs_changes, failed, done이다. 컷의 art·layout·composed·qa별 상태와 next_action을 저장한다.

## 승인 시점

| 대상 | 사용자에게 보여줄 내용 | 다음 단계 |
| --- | --- | --- |
| 스타일 | 서로 다른 샘플과 표현 규칙·출처 | 캐릭터 제작 |
| 캐릭터 | 명세와 정면·3/4·표정 시트 | 해당 캐릭터로 콘티 확정 |
| 콘티 | 컷별 사건·표정·대사와 읽는 순서 | 컷 이미지 생성 |
| 최종 | 모든 컷과 1920·1080 결과, 순서 | 승인 파일 출력 |

실제 사용자 응답을 대상 버전에 연결한다. 대기 시간, 도구 성공, 에이전트 판단을 승인으로 해석하지 않는다. 사용자의 명시적인 승인 방식 변경 지시가 있으면 해당 범위에 적용하고 기록한다. 수정된 버전에 예전 승인을 붙이지 않는다.

## 부분 수정

| 요청 | 영향 |
| --- | --- |
| 오탈자·대사 | 콘티 텍스트 QA·승인, 해당 합성·최종 승인; 의미가 바뀌면 그림도 재검토 |
| 말풍선 이동 | 해당 배치·합성·QA·최종 승인 |
| 표정·구도 | 해당 그림·합성·QA·최종 승인; 사건이 바뀌면 콘티부터 |
| 결말·사건 | 영향 콘티 승인부터, 전체 이야기 흐름 재검토 |
| 캐릭터 변경 | 새 캐릭터 버전 승인, 적용 컷 갱신 |
| 스타일 변경 | 새 스타일 승인, 캐릭터 적합성 재검토, 영향 그림·식자 갱신 |
| 컷 순서 변경 | 콘티 승인·읽는 흐름·최종 승인과 출력 순서 갱신 |

변경 없는 파일은 재사용하되 episode.json의 exports에서 정확한 파일을 참조한다. 과거 에피소드를 자동으로 새 스타일·캐릭터로 변경하지 않는다.

## 실패 처리

품질 미달은 대상·단계별 최초 시도 후 자동 수정 최대 2회다. 기술 오류는 별도로 최초 요청 후 재시도 최대 2회다. 인증·잘못된 입력은 즉시 원인을 해결한다. 외부 요청의 응답이 불명확하면 완료 여부를 먼저 확인한다. 실행 기록을 통해 재개해도 횟수를 유지한다.

한도에 도달하면 마지막 유효 결과와 실패 이유, 대안을 제시하고 판단을 받는다. 검토할 수 없는 항목은 unable_to_assess로 남긴다. 필요한 기능이 없으면 가능한 산출물을 저장하고 다음에 필요한 기능을 알린다. 결과를 만들지 못했는데 성공으로 넘기지 않는다.

## 저장 정책

v2 현재 정보는 series.json과 episode.json으로 통합한다. 변경 기록은 에피소드별 history.jsonl 하나에 누적하며, 별도 단계별 JSON 및 revision 폴더의 snapshot을 만들지 않는다. 파일 저장 위치와 API는 contracts.md와 tools.md를 따른다.
