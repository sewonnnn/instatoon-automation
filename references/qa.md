# 제작 QA 기준

[원본 QA 기준표](../docs/QA기준표.md)의 항목을 실제 제작 단계에 배치한 실행 기준이다. 판단 결과에는 대상 revision, 단계, 검사 방식(code 또는 visual 또는 text), 판정, 문제의 위치와 근거, 수정 제안을 기록한다.

판정은 pass, needs_changes, unable_to_assess다. 개별 문제의 심각도는 blocking 또는 advisory다. 검사를 하지 못했으면 pass로 적지 않는다. blocking이 남거나 필수 검사가 불가능하면 해당 단계 완료로 넘기지 않는다. advisory는 개선 제안이며 자동 재생성을 강제하지 않는다.

| 단계 | 필수 확인 |
| --- | --- |
| 스타일 | 출처·샘플 확인, 요청 분위기 적합성, 샘플과 명세의 일치, 펜선의 일관성과 상대 굵기, 접점 때문에 공간감이 사라지는지 |
| 캐릭터 | 정면·3/4·표정 간 같은 인물인지, 고정 특징과 승인 스타일의 일치 |
| 콘티 | 최대 10컷, 단편 완결 또는 연재의 질문, 읽는 순서, 대사 양·길이·필요성, 인물·대사 배치의 쏠림과 여백 계획 |
| 그림 | 상황과 그림, 표정과 대사의 일치, 원본 시트와 동일 인물인지, 배경 필요성, 더 적절한 구도, 그림만으로 대사 제거 가능성 |
| 식자 | 실제 읽는 순서, 대사 대비 말풍선 크기, 한쪽 쏠림·과도한 빈 여백, 넘침·글리프 누락·화자 혼동·인물 가림, 축소본 가독성 |
| 출력 | 컷 수·순서, 두 크기의 PNG, 최종 승인 버전·해시 일치, AI 생성물 표시 |

콘티의 공간 항목은 텍스트 단계에서는 계획을 검토하고, 실제 크기·충돌은 식자 단계에서 확정한다. 의미 있는 침묵이나 감정 표현을 위한 여백은 결함으로 단정하지 않는다.

## 판정 예시

- blocking: 말풍선 꼬리가 다른 인물을 가리킨다. 해당 컷의 레이아웃을 수정한다.
- blocking: 캐릭터 시트와 다른 얼굴색이 생성됐다. 해당 그림을 수정한다.
- advisory: 클로즈업이면 감정이 더 잘 보일 수 있다. 현재 구도로 전달되면 선택 개선이다.
- unable_to_assess: 결과 이미지 파일을 열 수 없어 표정을 검토하지 못했다. 파일 접근을 해결한 후 검사한다.

QA 문서의 issues에는 대상 panel_id 또는 자원 ID, criterion, severity, evidence, suggested_action을 둔다. 재시도와 변경 범위는 [진행 규칙](workflow.md)을 따른다. 사용자 승인은 QA와 별도 기록이다.
